# 动图换背景（live-swap-bg）

真实拍摄的手和商品原样保留，只换背景。不用视频生成模型，所以商品不会变形、包装字不会写错。
整条链路在本地 GPU 上跑（Apple 芯片 Mac 实测；CUDA 理论可用、未测）。

每一步都会打印一段 JSON 并把文件写进工作目录，目录约定见 `live_swap_bg/clip.py` 顶部注释。
**指标只能告诉你去看哪几帧，不能代替人眼。** 每个"看"的步骤都要真的打开图片看，看不出来的观感问题要明说交给用户。

## 0. 准备

- 第一次用：`live-swap-bg download-models`（约 1.3 GB，放到 `./models` 或 `$LIVE_SWAP_BG_MODELS`）。
- 用户要提供：一段手持商品的视频（最好是 iPhone Live Photo 的 `.MOV`，才能导出 Live Photo），一张新场景图。
- 场景图用任何生图工具都行。提示词模板见 `demo/eucerin/background-prompt.txt`：只要背景、不要人和商品、不要文字、竖版 3:4、中间留空、
  明暗和原片接近（白瓶子别配纯白背景）。

## 1. 选片（不合格的片子后面怎么修都修不好）

先跑 `live-swap-bg check <video>`，然后逐条看：

1. **背景要有纹理**：`trackable` 必须是 true（每对相邻帧至少 6 个点、3 个网格）。纯色墙算不出镜头运动，新背景会来回抖。
2. **手从画面左、右或下沿伸进来**，手和商品都**不能碰到上沿**：碰到上沿的切边会露在画面里。
   不连着画面边缘的手和商品，贴到新背景上会悬空。
3. **运动幅度适中**：`moving_area_percent` 太小说明商品几乎没动，太大说明整个画面都在动（抠图会把背景当成商品）。
4. **只留手里拿着的那一个商品**。桌上摆着的同款不要抠：新背景里没有那张桌子，它会悬在半空。
5. 高风险：透明长指甲 + 灰墙（指甲透出的就是墙色，分不开）、镶钻美甲配大理石墙（会被当背景挖掉）。

## 2. 准备帧

```bash
live-swap-bg init input.MOV work/<名字> [--start 秒 --end 秒]
```
超过 150 帧会拒绝（SAM 2 显存），用 `--start/--end` 截一段。

## 3. 种子掩膜（最关键的一步）

打开 `work/<名字>/seed-grid.jpg`（种子帧加 60px 坐标网格），**在全尺寸图上量坐标，不要在缩略图上估**。写 `prompts.json`：

```json
{"groups": [
  {"name": "bottle", "box": [160,135,465,960], "pos": [[310,160],[300,480],[176,560]], "neg": [[520,300],[120,300]]},
  {"name": "hand",   "box": [0,580,200,960],   "pos": [[60,700],[100,820],[12,940]], "neg": [[60,520]]}
]}
```

- **商品一组、手一组**，必要时细部件单独一组（手指、钻甲、泵头）。正点铺满主体，尤其是**和背景颜色接近的边**（白瓶对白墙的那一侧）。
- 负点打在必须排除的东西上：旁边的第二个瓶子、桌面、**指缝**。指缝里放了负点，后处理就不会把它填成前景。
- SAM 漏掉的一块（比如瓶肩被白墙吃掉）：用 `add_polygons` 沿真实边缘画多边形补上。抠多了：`clear_boxes`。

```bash
live-swap-bg seed work/<名字>
```
**看 `seed-review.jpg`**（背景压暗、红线是轮廓、绿点正、蓝点负）：轮廓必须贴着真实边缘。
瓶肩、手掌下缘、指尖、指甲这些地方最容易漏，漏了就补点或补多边形再跑，直到满意。

## 4. 跟踪 + 抠图

```bash
live-swap-bg track work/<名字>              # 透明/磨砂瓶身跟几帧就丢：删掉 masks/ 和 tracking.json，加 --multi 重跑
live-swap-bg matte work/<名字>              # 有泵嘴、喷头、刷头这类细部件：加 --thin
```
重跑任何一步之前要先删掉它的输出和结果 json（`tracking.json`、`matting.json`），工具会拒绝覆盖，不会悄悄跳过。

`tracking.json` 里 `largest_area_jump` 大于 5 个百分点，说明有帧跟丢或跟多了，去看那几帧。

## 5. 时间稳定（按需，不是必跑）

```bash
live-swap-bg stabilize work/<名字> --vote-masks      # 掩膜边缘来回闪（指甲、瓶盖高光）；跑在 matte 之前
live-swap-bg stabilize work/<名字> --fill-dropouts   # 透明瓶身/泡沫单帧掉成背景；安全，只往上补
live-swap-bg stabilize work/<名字> --median-alpha    # 软边缘仍在闪；会把快速移动的指缝拖成实心、把指甲挖空，慎用
```
- `--vote-masks` 会把**快速移动的细长指甲叠成"叉子"**：跑完要对比 `masks-before-vote/` 和 `masks/` 里动得最快的几帧。叉了就不用它。
- 每个操作都把原始输入留在 `<目录>-before-<操作>/`，重跑从那里读，不会叠加。

## 6. 镜头运动

```bash
live-swap-bg motion work/<名字>             # 原背景几乎无纹理会报错，提示加 --static
```
逐帧残差中位数超过 1.5px 会自动改成静止背景（估计在跟噪点和灯光闪烁跑，不是在跟镜头），原估计留在 `motion-lk.json`。
残差低时位置有点高频抖动是真实手抖，背景应该跟着动，不要改静止。

## 7. 背景板

```bash
live-swap-bg plate work/<名字> scene.png [--blur 3] [--frame-space]
```
做人像虚化，并只把前景边缘一圈调成原墙的颜色（残边、半透明处透出的都是原墙色，这一圈接近了就看不出来），圈外保持原场景。
镜头移动很大、场景道具被挤出画面时加 `--frame-space`。

## 8. 渲染 + 自查

```bash
live-swap-bg render work/<名字>             # 商品是放在台面上而不是手拿：加 --rests-on-surface
live-swap-bg crops work/<名字>              # 首 3 帧、末 4 帧、动得最快的一帧，原分辨率裁图
live-swap-bg jitter work/<名字>             # 新背景抖不抖
```

报"完成"之前必须做：
1. 看 `out/review-*.jpg`（每一帧的缩略图）和 `out/edge-crops.jpg`（原分辨率）。重点：指腹、长指甲、钻甲、瓶身和手之间的缝、指缝阴影、透明瓶身外缘。
   **首尾帧最容易出问题**（时间滤波在片头片尾是单边窗口），一定要看。
2. `jitter` 的 `high_frequency_std_px` 应该在 0.5 以下；超过了就是背景在抖，回到第 6 步考虑 `--static`。
3. **播放视频**。有一类闪烁只有播放才看得出：指缝在原墙和新墙之间一帧一跳。用
   `live-swap-bg flicker work/<名字> x0 y0 x1 y1` 对可疑区域做逐帧尖峰扫描，它会出一张 k-1 | k | k+1 | alpha 的放大拼图。
4. 任何自动修补之后，同一位置修补前后并排再看一遍，修补本身会把深色皮肤边缘挖缺。

常见问题和修法：

| 现象 | 原因 | 修法 |
|---|---|---|
| 边缘一圈白边或黑边 | 抠出来的半透明边带着原墙色 | 默认的边缘修复会洗掉；暗背景上亮商品自带的深色细边会被一起压淡，这类片子用 `--no-edge-repair` |
| 指缝里一块灰楔子 | 原背景被抠成了前景 | 回第 3 步在指缝放负点重做种子；完全封闭的小洞确认是原墙后可用 `--max-gap-pixels` |
| 手指或指甲缺一块 | 种子漏了 / 投票把它削了 | 补正点或多边形重做种子；不用 `--vote-masks` |
| 新背景每几帧跳一下 | 原墙纹理太少，镜头估计在跟噪点 | `motion --static` |
| 商品悬空、斜靠着不倒 | 抠了没有手托着的物体 | 种子只留手里那一个 |
| 画面里出现平直切边 | 手或商品碰到了原片上沿 | 换片子 |

观感问题（主体够不够突出、背景搭不搭、透明长甲像不像）指标判断不了，**明确告诉用户需要他看**。

## 9. 导出 Live Photo（macOS）

```bash
live-swap-bg livephoto work/<名字>
```
需要输入是 iPhone Live Photo 的原始 `.MOV`（用它的元数据轨道让照片 App 认出这是 Live Photo）。
输出 `out/livephoto/<名字>.JPG` + `.MOV`，配对 ID 已校验一致；手机型号、拍摄时间、位置等元数据不会写进去。
把两个文件一起拖进 Mac 的「照片」App，或一起 AirDrop 到 iPhone，配对正确时会合成一张 Live Photo。
工具只校验了文件结构（配对 ID、静帧标记），导入后请让用户在手机上长按确认它是 Live Photo。
